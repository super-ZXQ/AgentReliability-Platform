# 开发提示词

你是 AgentReliability Platform 的开发代理。平台化入口与适配器已实现。现在继续完成发布前验收，按顺序执行下列任务，每完成一项并验证后直接推进下一项。

## 阅读顺序

1. [平台化大阶段](PLATFORM_BUILDOUT.md)定义各模块、复现范围和外部依赖。
2. [项目目标](PROJECT_GOAL.md)说明用户和交付目的。
3. [V1 架构](ARCHITECTURE.md)与[V1 实施计划](IMPLEMENTATION_PLAN.md)说明现有接口及 M1 至 M4 的验收证据。

## 当前任务 · 发布前验收

1. 核对当前提交、`artifacts/platform/verification.json` 和原始运行产物。复跑 pytest 与 20 条离线回归。发布验收使用新的产物目录，保留历史证据。
2. 修正质量闭环的判定。已有订单场景记录的 `expected_category_match=false`，两项 Docker 补丁复测通过，当前总判定仍为 `PASS`。将调查流程完成、根因与证据验证、补丁复测、人工审核分别呈现。诊断与金标不符或证据不足时，总结论应反映诊断仍需审核，保留已验证的补丁结果。增加回归测试，覆盖诊断错误但补丁通过，以及诊断与复测均通过。金标仍只用于判定器。
3. 复跑真实扫描与 Docker 订单场景，并检查 2×2 矩阵报告。现有离线矩阵 16 次执行完成，根因正确数为 0。报告分别统计流程完成数、可判定样本数、根因正确数和错误数。追溯根因差异来自模型输出还是数据映射，记录证据。
4. 补真实服务实测。先完成一个配置好的模型在电商套件上的 6 条 × 3 次实测。按已具备的模型配置、人工审核标签与本地实例，继续 OpenJudge、真实 2×2 矩阵及 A.I.G。分别记录实际试验与历史、离线及替身结果。外部依赖缺失时写明具体缺项和复测命令，并继续其余工作。
5. 整理发布候选的 README、验收报告与演示入口，列出可追到源码版本的证据。CI 记录应来自待发布版本。按授权用正常 PR 触发当前离线门禁，远端发布及设置按用户授权操作。

## 收尾条件

所有当前可执行项实现并完成验证后统一交付。报告注明每项是已验证、验证失败，还是依赖外部配置待补验，并列出证据及继续命令。真实模型和服务的结果按实测呈现。

## 交付回报

提交清晰的 README 复现步骤和一次完整的阶段报告。列出主要改动、已执行命令及退出码、运行环境、产物路径，以及仍需补验的项目。将历史 CI、本地离线、替身测试和真实服务结果分开记录。
